# security — 脅威検査

脅威モデルと設計判断は [`docs/SECURITY.md`](../docs/SECURITY.md) にあります。
ここに書くのは**この実装が何を主張し、何を主張しないか**です。

## 位置

```
ページ → observe() → 【 shield() 】 → constrain() → LLM
                          ↑
              ここを通らないバイトは LLM に届かない
```

`agent/src/run.ts` の各ステップで `shield(raw)` を呼び、その戻り値だけが下流に流れます。
判定（`judge()`）も同じ `safe` を受け取ります。**심판도 LLM 호출이라 예외를 두면 우회로가 됩니다.**

元の観測（`raw`）はトレースの `steps[].raw` にそのまま残ります。
消した後を証拠として残すと、**何を防いだのかを後から誰も確認できません。**

## 誤差の向き

マスキング（`lexicon/`）は**過少**に倒します。根拠なく隠さないためです。
脅威検査は逆に過剰に倒したくなりますが、そうしません。

> 過剰な遮断 = 正常な文を消した状態でエージェントを走らせる
> → 失敗する → その失敗が「サイトが難しいから」なのか「我々が消したから」なのか区別できない
> → この製品の計測値が全部無効になる

そこで規律を二つに割っています — **検出は広く（info / warn）、遮断は狭く（block）。**
実際にバイトを消すのは、「人間の読者に向けた文章としては読めない」ものだけです。

`security/inspect.test.ts` の約半分は**誤検出テスト**です。
検出テストだけなら「全部 block」という最悪の実装も通ってしまいます。

## 主張すること / しないこと

| しない主張 | する主張 |
|---|---|
| 「プロンプトインジェクションを防げます」 | 「`security/patterns.ts` の表に載っている形は、LLM に渡る前に除去されます」 |
| 「AI が指示を見破ります」 | 「**モデルはその文字列を見ていません。**除去は判断ではなく前段の処理です」 |
| 「PII を検出します」 | 「公開 www にあってはならない 3 種（個人番号・基礎年金番号・カード番号）だけを見ます。公開されている連絡先は対象外だと明示します」 |

3 行目が重要です。電話番号やメールアドレスは自治体サイトに**あるのが正常**で、
それを PII として記録するとトレースが埋まり、本当の 1 件が埋もれます。
より広い検査は上流（OrcaRouter PII Shield）が持ちます。ここはその手前の狭い網です。

## 限界（先に言う）

- **パターン表にない形は素通りします。** 表は `security/patterns.ts` にあり、そこが主張の範囲です。
- 除去できるのは**我々の観測パイプラインを通るもの**だけです。
- ライブ検証が示したのは「除去されたので**モデルが見ていない**」であり、
  「モデルが指示に抵抗した」ではありません。前者のほうが強い性質ですが、別のものです。

## コマンド

```bash
npm run security:test    # 単体テスト（検出 + 誤検出）
npm run honeypot         # ローカルフィクスチャで検出と除去を確認。原価 0
npm run honeypot:live    # エージェントを実走させ、指示に従わないことを確認。LLM 呼び出しあり
```
