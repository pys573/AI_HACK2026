# missions/keys/ — 정답 키

> **이 디렉터리의 내용은 LLM에게 절대 가지 않는다.**

## 왜 물리적으로 분리했는가

정답을 프롬프트에 한 글자라도 넣으면, 그 실행은 「탐색」이 아니라 「받아쓰기」가 된다.
그리고 우리는 그걸 **증명할 수 없게 된다.** 심사에서 「정답을 미리 알려준 것 아닙니까」에
답할 수 있어야 하는데, 같은 파일 안에 있으면 코드를 다 읽혀야 한다.

디렉터리가 다르면 한 줄로 답할 수 있다: **`decide()`는 `missions/keys/`를 import 하지 않는다.**

## 규율

| | |
|---|---|
| 읽어도 되는 곳 | `agent/src/judge.ts` **한 곳뿐** |
| 읽으면 안 되는 곳 | `decide.ts` · `prompts.ts` · `act.ts` · `run.ts` |
| 강제 방법 | `agent/src/mission.ts`가 `loadMission()`(키 없음)과 `loadKey()`(키만)를 나눠 제공한다 |

## 판정이 2단인 이유 (R6)

키 대조만으로는 부족하다. URL이 바뀌어도 정답이고, 정답 페이지에 도달했는데
URL 패턴이 안 맞을 수도 있다. 반대로 LLM 판정만 쓰면 관대해진다 —
「近いページに着いたので到達とする」를 하기 시작한다.

그래서 **키 대조와 LLM 판정을 각각 독립으로 돌리고, 어긋나면 `Verdict.disagreed = true`로 남긴다.**
숨기지 않는다. 어긋난 비율 자체가 이 지표의 신뢰도다.

## 이 키들의 현재 상태

⚠️ **v0 — 미검증.** 사이트 구조를 직접 확인하기 전에 작성한 잠정값이다.
`control` 프로필(제약 없음) 실행으로 검증한 뒤 확정한다.
control이 도달하지 못하면 **키가 틀렸거나 미션이 과하다.** 둘 다 우리 잘못이지 사이트 잘못이 아니다.
