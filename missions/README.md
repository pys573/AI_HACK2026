# missions/

에이전트에게 주는 「용무」. **정답은 여기 없다.**

| 파일 | 무엇 |
|---|---|
| `public.json` | 준비된 미션 9건. 105회 실측이 전부 여기서 나왔다 |
| `security.json` | 검증용(로컬 허니팟). 통계에 섞이지 않게 **일부러 분리**돼 있다 |
| `keys/` | ⚠️ 정답 키. **`agent/src/judge.ts` 외에서 읽지 않는다** |
| `tasks.json` | **즉석 실행용 용무 후보** ← 2026-08-12 추가 |

## `tasks.json` — 화면에서 고르는 「用事」

즉석 실행(`agent/src/live.ts`)은 URL을 그 자리에서 받는다. 그러면 미션이 미리 없으므로
**용무만 고르게 하고 URL과 합쳐서 즉석 미션을 만든다.**

```
받은 URL  +  tasks.json의 한 줄  →  Mission (id: live__<task>__<host>__<시각>)
```

`goal_ja`가 **「このサイトの中で」로 시작하는 이유**: 준비된 미션은 「新宿区の転入届」처럼
사이트 이름이 문장에 박혀 있다. 즉석 미션은 어느 사이트가 올지 모르므로 그렇게 못 쓴다.
사이트 이름을 넣지 않은 채로 「이 사이트 안에서 찾아라」로 범위를 준다.

### ⚠️ 정답 키가 없다

`keys/`에는 이 조합의 정답이 없다. 있을 수가 없다 — 어느 사이트가 올지 모르기 때문이다.
그래서 즉석 실행의 도달 판정은 **AI 하나뿐**이 된다 (준비된 미션은 사람이 만든 키 + AI의 2단 판정).

이 사실은 숨기지 않고 세 곳에 남는다:

1. `Judgement.key_available` — 판정 결과 안
2. `Verdict.reason_ja` 끝의 「※ このURLには人が用意した正解キーがないため…」
3. 진행 상황(`Progress.start.key_available`) → 화면

**즉석 실행 결과를 105회 실측과 같은 급으로 말하지 않는다** (절대규칙 4).

### 결과가 저장되는 곳

즉석 실행은 `agent/runs/`가 아니라 **`agent/live/`**에 쓴다.
`scripts/build-web-data.ts`가 `agent/runs/` 전체를 훑어 화면의 모든 숫자를 만들기 때문이다.
같은 폴더에 두면 심사장에서 넣은 URL이 105회 통계에 섞인다.
