# 화면에 얹히는 것들 — 검출기 확인용 픽스처

`agent/src/observe.ts`의 `Overlay` 판정이 **켜져야 할 때 켜지고, 켜지면 안 될 때 안 켜지는지**를
남의 사이트에 의존하지 않고 확인하기 위한 것이다.

```bash
npm run overlay:test     # 실제 Chrome으로 7장을 열어 본다. LLM 무호출 = 원가 0
```

두 단으로 나뉘어 있다. 앞은 **무엇을 「덮였다」고 말하는가**(판정), 뒤는 **실제로 눌러서
어떻게 되는가**(`act()`). 뒤쪽은 브라우저 안에서 마우스가 실제로 움직여야만 확인되므로,
여기가 아니면 그 경로는 한 번도 안 돈 채로 제출된다.

## 왜 픽스처인가

2026-08-15에 東京電力 톱으로 확인하려 했으나, 문제의 안내 채팅은 **제3자 스크립트**라
그날 그 시각에 실리지 않았다. 남의 사이트의 상태에 검증이 걸려 있으면
**무대에서 재현되지 않는다**(절대규칙 7). 그래서 우리 손 안으로 가져왔다.

보안 쪽 `fixtures/honeypot/`과 같은 규율이다 — 모델을 안 부르므로 네트워크가 죽어도 산다.

## 6장이 각각 무엇을 잠그는가

| 파일 | 기대 | 왜 이걸 시험하는가 |
|---|---|---|
| `chat-open.html` | 🔴 덮임 · 닫기 `named` | 東京電力에서 실제로 일어난 것. 채팅이 열려 화면을 덮고, 그 뒤 클릭이 전부 삼켜졌다 |
| `glyph.html` | 🔴 덮임 · 닫기 `glyph` | ✕가 이름 없이 **글자 하나**로만 있는 흔한 경우 |
| `nameless.html` | 🔴 덮임 · 닫기 `corner` | 이름도 글자도 없고 **오른쪽 위에 있다**는 것뿐인 경우. 가장 약한 근거라 순위가 제일 낮다 |
| `no-close.html` | 🔴 덮임 · 닫기 **없음** | ★ 닫는 수단이 정말 없는 사이트. 이건 우리 실패가 아니라 **사이트에 대한 발견**이다 |
| `dead-x.html` | 🔴 덮임 · 닫기 `named` | ★ ✕를 제대로 찾아 눌렀는데도 **안 닫힌다**. 찾는 것과 닫히는 것은 별개다 |
| `sticky-header.html` | ⚪️ 안 덮임 | 위에 붙어 다니는 머리띠. 가리긴 해도 **막지는 않는다**. 여기서 켜지면 105회 전부가 오염된다 |
| `flow-menu.html` | ⚪️ 안 덮임 | ★ 東京電力의 실제 전체화면 메뉴 구조(`position: static`, `z-index: 200001`, 화면의 106%). **얹힌 게 아니라 페이지가 바뀐 것**이고, ✕도 `<a>`라 이미 우리 목록에 「menu」라는 이름으로 들어 있다 — 손댈 이유가 없다 |

마지막 두 장이 이 묶음의 존재 이유다. **안 켜지는 것을 지키는 쪽이 켜지는 것보다 중요하다** —
한 번이라도 헛되이 켜지면 그 사이트의 옛 기록과 조건이 달라지고, 사이트 간 비교
(渋谷区 4% ↔ 港区 95%)가 근거를 잃는다.

## 이건 목업이 아니다

여기 있는 HTML은 **우리가 쓴 것**이지 어느 사이트의 복제가 아니다. 다만 구조는
2026-08-15에 東京電力 톱에서 실제로 관측한 값에서 가져왔다 (`flow-menu.html`의
`position: static` / `z-index: 200001` / 106%는 그날 그 페이지에서 읽은 그대로다).

여기에는 인젝션을 심지 않는다. 그건 `fixtures/honeypot/` 쪽 일이다.
