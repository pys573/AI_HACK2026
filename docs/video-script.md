## B｜0:18–0:45　演技ではなく引き算

**画面**
左右2分割。左＝ふつうのページ、右＝エージェントが実際に見た画面。
`ウェブアクセシビリティ方針` → `ウェブ◯◯◯◯◯◯◯◯方針` に伏字が入る瞬間をスロー。
下に要素数カウンタ `270 → 9`。

**ナレーション**
> よくあるやり方は「72歳のふりをしてください」と指示することです。
> でもモデルは意味を**知ったまま**、知らないふりを演じるだけです。
>
> ツマヅキは、プロンプトではなく**観測層**で引き算します。
> 隠された後の画面しか、モデルは見たことがありません。

**画面テロップ**
```
ページ → observe() → shield() → constrain() → LLM
                                    ↑ ここを通らないバイトは届かない
```
`「アクセシビリティ」60歳以上の理解率 2.1%（国立国語研究所 外来語定着度調査）`

## E｜2:00–2:20　原価と OrcaRouter

**画面**
`/report/detail` の原価表。`cost_source: api` / `table` の列を指す。
ルーティング表（perceive / decide / judge / diagnose）。

**ナレーション**
> LLM 呼び出しは全部 **OrcaRouter** 経由です。飾りではなく成立条件で、
> 全部を高いモデルで回すと1レポートの原価がサブスク価格を超えます。
>
> ルーティングの入力は**ステップ種別ひとつ**。
> だから、どの原価がどのステップで出たかを後から説明できます。
>
> API が返した実費と、こちらが価格表で計算した値は**分けて記録**します。
> 推定値を実測とは呼びません。

## 撮影メモ

- **ライブ実行はしない。** 事前録画した素材だけを使う（絶対規則7）。
  ステージでタイムアウトすると死ぬ。
- `npm run honeypot` は **LLM を呼ばない**ので、ネットワークが死んでも回る。
  F の素材はこれで撮る。
- ナレーションは日本語。読み上げは1秒あたり5〜6文字を目安に尺を合わせる。
- 数字を映す画面には**必ずプロファイル ID とバージョン**を同じ画面に入れる。
- 「サイト監査」「アクセシビリティ検査」は**使わない**（不利な比較を招く）。
- 冒頭18秒で「何の道具か」が伝わらなかったら撮り直す。
  ③の採点観点が「触れて数十秒で価値がわかる」である。
