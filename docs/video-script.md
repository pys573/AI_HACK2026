## D｜1:20–2:00　結果 — サイトが割れる

**画面**
`/report`。サイト別の横棒。**いちばん高い棒といちばん低い棒が並ぶ1枚。**
その下に点グラフ（点1個＝実行1回）。

> ⚠️ 旧データの「0% ↔ 94%」は**使わない。** あれはガードの不具合が作った値だった
> （`FINDINGS.md` F12）。下の数字は `batchv2` 世代・有効 125 ラン。

**ナレーション**
> 同じ用事、同じ制約で、5つの自治体サイトを回しました。
>
> 制約なしなら、どのサイトでもほぼ到達します。制約をかけると割れました。
> **渋谷区は 96% 到達。港区は 5%。**
> 違うのはサイトだけです。
>
> しかも港区は、制約なしなら4回中4回とも到達しています。
> 通れない場所ではない。それでも制約をかけると 20回に 1回しか着かない。
>
> つまりこれは「AI ができない」のではなく、**サイトを測った値**です。
> 96% のサイトがあることが、どんなサイトでも悪く出る装置ではない証拠になります。

**画面テロップ**
```
同じ用事（転入届）・同じ制約・違うのはサイトだけ
渋谷区 23/24（96%）  ↔  港区 1/20（5%）
n＝125（制約プロファイル実行結果 / batchv2）
```

**★ ここで弱点も出す（3秒）**
> 対照群も 100% ではありません。21/23。落ちた2件は「転居届」と「転入届」の取り違えでした。
> 25マス中9マスは、同じ条件で結果が揺れています。マス単位では断定しません。

## E｜2:00–2:20　原価と OrcaRouter

**画面**
`/report/detail` の原価表。`cost_source: api` / `table` の列を指す。
ルーティング表（perceive / decide / judge / diagnose）。

**ナレーション**
> LLM 呼び出しは全部 **OrcaRouter** 経由です。飾りではなく成立条件で、
> 全部を高いモデルで回すと1レポートの原価がサブスク価格を超えます。
>
> ルーティングの入力は**ステップ種別ひとつ**。
> だから、どの原価がどのステップで出たかを後から説明できます。
>
> 125ラン全部で **4ドル23セント**。1ラン**約3.4セント**でした。
>
> ただし比較の相手は**計算値**です。API が返した実費と、
> こちらが価格表で計算した値は**分けて記録**します。推定値を実測とは呼びません。

**画面テロップ**
```
実際に払った額（125ラン）           $4.23
全部を anthropic/claude-opus-5 なら  $39.98 ← 価格表からの計算値
                                    89.4% 減
```
（★ 右側に `cost_source: table` のラベルを必ず出す。実測と並べない）

## 撮影メモ

- **ライブ実行はしない。** 事前録画した素材だけを使う（絶対規則7）。
  ステージでタイムアウトすると死ぬ。
