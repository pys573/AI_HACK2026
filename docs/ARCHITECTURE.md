# アーキテクチャ

## 全体像

```
┌─ ランナー（ローカル / Node 25 + Playwright + システム Chrome） ────────────┐
│                                                                          │
│   observe()      ページ → 生の観測（URL・テキスト・要素一覧・スクロール）  │
│      ↓                                                                   │
│ ★ constrain()    制約プロファイルを適用                                   │
│      │            ・語彙マスク（リンクラベルの中も）                       │
│      │            ・ビューポート外の要素を落とす                           │
│      │            ・使える道具を減らす（ページ内検索・サイト内検索）        │
│      ↓                                                                   │
│   decide()       [LLM] 次に何をするか                                     │
│      ↓                                                                   │
│   act()          クリック / スクロール / 戻る … 忍耐予算を減らす           │
│      ↓                                                                   │
│   judge()        [LLM] ゴールに到達したか（正解キーとの照合も別途）         │
│      ↓                                                                   │
│   diagnose()     [LLM] なぜ失敗したか・何を直すか                          │
│                                                                          │
└──────────────────────────────┬───────────────────────────────────────────┘
                               │  RunTrace（JSON）
                               ▼
                         Supabase（Postgres + Storage）
                               │
                               ▼
              Web（Next.js / Vercel）— リプレイ再生・レポート
```

**この図の中心は `constrain()` の 1 行です。**
LLM に渡るバイトはすべてここを通ります。迂回路が 1 本でもできた時点で、
このプロダクトは「演技する AI」に戻り、それは既に存在し既に批判されているカテゴリです。

## 中心となるデータ構造

`core/types.ts` にすべての型があります。このファイルは**何も import しません**。
Web（Next.js）がそのまま読めるようにするため、Playwright や Node への依存を持ち込まないためです。
したがって Buffer ではなくストレージキーを、Date ではなく ISO 文字列を使います。すべて JSON 直列化できます。

### `Step` が観測を 2 つ持つ理由

```ts
type Step = {
  raw:  ObservationSnapshot;   // 制約前 — LLM は一度も見ていない
  seen: ObservationSnapshot;   // 制約後 — LLM が実際に見たもの
  ...
}
```

片方だけ保存すると、後から作り直せません。両方あることで:

- Before / After の比較がそのまま画面になる
- 「サイトが難しいのではなく、制約が原因だった」を事後に証明できる
- マスクの妥当性を第三者が検証できる（何を伏せ、何を伏せなかったか）

### 原価は 1 呼び出しずつ記録する

```ts
type CostRecord = {
  step_type; model; prompt_tokens; completion_tokens; cached_tokens;
  cost_usd; cost_source: "api" | "table"; latency_ms; route; mode; retries;
}
```

`cost_source` が重要です。API が原価を返した場合は `"api"`、こちらが価格表で計算した場合は `"table"`。
**推定値を実測と呼びません。** 詳細は [ROUTING.md](./ROUTING.md)。

### 正解をプロンプトに入れない

到達判定の根拠（`MissionKey`）は人が事前に手で作り、**LLM には見せません。**
正解をプロンプトに入れた瞬間、「到達した」は測定ではなく自己成就予言になります。

## 技術選定

| 領域 | 採用 | 理由 |
|---|---|---|
| 実行環境 | Node 25（`.ts` を直接実行） | ビルド不要。型ストリップで実行できるため、並列作業中に誰かのビルドを待つ状況が発生しない |
| ブラウザ | Playwright + **システムの Chrome** | バンドルされた Chromium は指紋が異なり、公共サイトの WAF に弾かれやすい |
| LLM | **OrcaRouter**（OpenAI 互換） | ステップ種別ごとのモデル選択。[ROUTING.md](./ROUTING.md) |
| 保存 | Supabase（Postgres + Storage） | トレース JSONB を原本として持ち、集計は SQL ビューで出す |
| Web | Next.js / Vercel | リプレイ再生とレポート |

### 採用しなかったもの

| | なぜ採用しないか |
|---|---|
| **Browser Use などの既存エージェント** | サイトを「使いこなす」ために作られています。DOM を読んで正解にたどり着いてしまうので、使いにくさの測定には使えません。私たちが必要なのは逆側です |
| **エージェントフレームワーク（LangChain 等）** | ループが 4 ステップしかありません。抽象化の利得より、制約の適用点が見えなくなる損失のほうが大きい |
| **賢くないモデルを使って「不慣れなユーザー」を表現する** | 一番やりたくなる近道ですが、これをやるとツール層の制約という差別化が消え、再現性も失われ、「結局は安いモデルに演じさせているだけでは」という批判に何も返せなくなります。**制約はツール層に置き、モデル選択はペルソナと直交させます** |
| **ルーティングを自前で書く** | 新しいモデルが出るたびに壊れます。そこは競争領域ではありません |

## 作業単位とディレクトリ所有

複数セッションが git worktree で同時に動きます。**自分のディレクトリの外は触りません。**

| 単位 | 名前 | 所有ディレクトリ |
|---|---|---|
| W0 | 基盤（契約） | `core/`, `db/`, ルート直下 |
| A | ENGINE | `agent/`, `missions/` |
| B | ROUTER | `llm/` |
| C | SECURITY | `security/`, `fixtures/` |
| D | WEB | `web/` |
| E | DATA | `lexicon/`, `profiles/` |
| F | INFRA | `db/`, `.github/`, デプロイ |
| G | DELIVERY | `docs/` |

`core/types.ts` は**全ワークツリーで読み取り専用**です。変更が要る場合は main で行い、各自が rebase します。
ここが揺れると並列作業が全部壊れます。

## データベース

`db/schema.sql`。設計方針は「**RunTrace（JSONB）が原本、残りのカラムは全部クエリ用の写し**」です。

リプレイ画面は `runs.trace` だけ読めば動きます。
原価・離脱率・マスク集計は正規化テーブルから SQL で出します。
原本を丸ごと持っているので、後からカラムが必要になっても再実行せずに backfill できます。

| テーブル | 用途 |
|---|---|
| `batches` / `runs` | 実行単位。プロファイル ID とバージョンは必ずセットで持つ |
| `steps` | 集計用の数値のみ（スナップショット本体は `runs.trace` の中） |
| `llm_calls` | **原価の元帳。** ここが空だとコストの主張は根拠を失う |
| `masks` | どの語が何回リンクを潰したか |
| `threats` | 検出した脅威。握りつぶさない |
| `findings` | 診断結果＝レポート本文 |

ビュー: `v_cost_by_step_type` / `v_cost_by_model` / `v_dropout` / `v_top_masks` / `v_threats`。

`v_cost_by_step_type` には `all_measured`（`bool_and(cost_source = 'api')`）が入っています。
表計算が 1 件でも混ざっていれば false になり、その数字を「実測」とは呼べないことが分かります。

## 対象サイトへの姿勢

- **読み取りのみ。** 会員登録・マイナンバー認証・フォーム送信・ログイン・電子申請システムへは入りません。
- 同一ドメインへの同時実行は 1、リクエスト間隔は 4 秒以上、robots.txt に従います。
- インジェクション検証用のハニーポットは**ローカルのフィクスチャにのみ**設置します。他者のサイトには置きません。
- ライブクロールに依存しません。デモは事前収録します。
