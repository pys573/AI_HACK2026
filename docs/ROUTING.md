# ルーティングと原価計測

LLM 呼び出しはすべて [OrcaRouter](https://www.orcarouter.ai/) 経由です。
装飾ではなく、**このプロダクトが成立するための条件**です。

## なぜルーティングが必要なのか

1 回の実行は「画面を読む → 次の手を決める」をステップごとに繰り返します。
1 サイトあたり 5 プロファイル × 2 バリアント = 10 実行、各実行が数〜十数ステップ。
ステップごとに 2 回の LLM 呼び出しが走るので、**1 レポートで LLM 呼び出しは数百回**になります。

全部をフロンティアモデルで回すと、1 レポートの原価が想定サブスクリプション価格を超えます。
つまりここは最適化の話ではなく、**プロダクトが売り物になるかどうかの話**です。

## ステップ種別 — ルーティングの唯一の入力

ルーティングの入力を 1 つに絞りました。**そのステップが何をしているか**です。

| ステップ種別 | 何をするか | 必要な賢さ | 呼び出し回数 |
|---|---|---|---|
| `perceive` | 今どんな画面かを要約・分類する | 定型処理 | ステップごと |
| `decide` | 次にどれを押すか | 判断だが選択肢は有限 | ステップごと |
| `judge` | ゴールに到達したか | 誤判定のコストが高い | 実行ごとに 1 回 |
| `diagnose` | なぜ失敗したか・何を直すか | レポート本文そのもの | 実行ごとに 1 回 |

呼び出しの大半は `perceive` と `decide` です。ここが安くなければ製品になりません。
一方 `diagnose` は顧客が実際に読む文章なので、ここをケチると製品価値が消えます。

### 責務の分離

```
エージェント側は、モデル名を知りません。       → step_type を付けるだけ
ルーター側は、ミッションを知りません。          → step_type だけを見てモデルを選ぶ
```

この分離があるので、**どの原価がどのステップで発生したか**を後から説明できます。
`llm/orca.ts` の `resolveModel(req)` が唯一の接点です。

## 削減施策

1. **ステップ種別ごとのモデル選択**
   定型処理を最安モデルへ、レポート生成のみ上位モデルへ。

2. **プロンプトキャッシュ**
   10 体のエージェントは、同一のシステムプロンプトと同一の仕様プレフィックスを共有します。
   キャッシュが効く前提を設計側で作っています。

3. **制約そのものがコスト削減になっている**
   これが一番おもしろい副作用です。
   ビューポート外の要素を落とし、語彙を伏せた結果、LLM に渡るペイロードは元より小さくなります。
   つまり**制約は機能であると同時に、原価削減施策**です。
   トレースには `chars_before` / `chars_after` が記録されます。

4. **A/B — ルーティングしなかった場合との比較**
   同じトレースを、全呼び出しフロンティアモデル単価で再計算します。

## 原価の出どころ

**推定値を実測と呼びません。** 原価はこの順で決めます。

| 順 | 取得元 | `cost_source` |
|---|---|---|
| 1 | API 応答が原価を返した場合 | `"api"` |
| 2 | `/models` から取得したライブ価格表で計算 | `"api"` |
| 3 | リポジトリ内のフォールバック価格表（`llm/pricing.ts`） | `"table"` |

「実測原価」と言えるのは 1 と 2 だけです。

フォールバック表はスポンサー資料の掲載値です。資料自体に「料金は 1 分ごとに更新」と明記されており、
つまりこの表は時々刻々ずれていきます。だから出典を型に持たせています。

```sql
-- 集計ビューにこれが入っています。1 件でも表計算が混ざれば false になります
bool_and(c.cost_source = 'api') as all_measured
```

また、価格表にないモデルは **0 円として数えません**（`estimateCost()` は `null` を返します）。
0 で数えると削減率が嘘になります。

```ts
export function estimateCost(model, promptTokens, completionTokens, prices) {
  const p = prices[model];
  if (!p) return null;   // 知らないモデルを 0 円にしない
  ...
}
```

## キャッシュ単価について

スポンサー資料には「5 分 / 1 時間のキャッシュウィンドウ」「キャッシュ単価で課金」とありますが、
**倍率は開示されていません。**

```ts
export const CACHE_INPUT_MULTIPLIER: number | null = null;
// 実測で確定するまで、この値を根拠に削減額を主張しない
```

分かっていないことは、分かっていないと書きます。
