# agent/demo/ — 발표에 쓰는 실측 트레이스

**이 안의 json은 목업이 아니다.** 실제로 브라우저를 열어 신주쿠구 사이트를 조작한
기록이고, `findings`는 `agent/src/diagnose.ts`가 실제로 모델을 불러 채운 것이다.
목업은 `core/fixtures/`에 있고 거기 README에 목업이라고 적혀 있다 — 섞지 않는다.

## 왜 커밋되어 있는가

`agent/runs/`는 `.gitignore`에 있다(실행할 때마다 쌓이는 출력이라서). 그래서
D(web)를 포함한 다른 워크트리에서는 실행 결과를 볼 방법이 없었다.
**절대규칙 7 — 라이브 크롤링에 의존하지 않는다.** 무대에서 쓸 것은 미리 녹화된
이 세 개이고, 그러므로 이건 출력이 아니라 **납품물**이다. 그래서 추적한다.

## 무엇이 들어 있나

| 파일 | 스텝 | 도달 | findings | 무엇을 보여주는가 |
|---|---|---|---|---|
| `control.json` | 5 | ○ | **0건** | 제약이 없으면 5스텝에 끝난다 |
| `senior-70s.json` | 17 | × | 5건 | 확대·어휘 제약 하에서 클릭 예산 소진 |
| `senior-70s-patient.json` | 34 | × | 6건 | 예산을 크게 줘도 도달하지 못한다 |

### ⚠️ control의 `findings: []`는 「아직 안 만들었다」가 아니다

**「막힌 곳이 없었다」는 결과다.** 대조군은 5스텝에 깨끗하게 도달했고, 그래서
검출된 신호가 0건이고, 그래서 모델을 부르지 않았다(원가 $0).

화면에서 이 둘을 같게 취급하면 안 된다. control이 0건이라는 사실 자체가
「제약이 원인이다」의 대조 증거이고, 이게 우리 주장의 절반이다.

## 갱신 방법

```bash
npm run diagnose -- <run_id>      # 그 실행의 trace.json에 findings를 써넣는다
cp agent/runs/<run_id>/trace.json agent/demo/<name>.json
```

브라우저를 다시 열지 않는다. 계측은 다시 못 돌리지만 진단은 몇 번이고 다시 돌린다.

## 이 트레이스로 주장할 수 있는 것 / 없는 것

- ○ 「이 프로필 v0의 실행 결과다」 — 파일 안에 `profile_id`·`profile_version`이 있다
- ○ 「findings의 근거 숫자는 코드가 셌다」 — `evidence`는 `agent/src/signals.ts` 산출
- × 「고령자는 이렇게 행동한다」 — n=1이고, 우리는 재현을 주장하지 않는다
  (`profiles/README.md`)
